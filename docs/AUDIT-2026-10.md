## Feature audit

### Gaps between what the product promises and what it does

1. **Landing drop only imports text (M).** Dropping an image, PDF or zip on the landing page is rejected, but the editor already encrypts and attaches those. The landing drop should create a clipboard and attach the files through the same path. This is the biggest promise-vs-reality gap.
2. **Paste an image (M).** Pasting a screenshot already attached in the editor; the landing page ignored it. Landing paste now creates a clipboard with the image attached.
3. **Pairing is invisible once done (S).** After a device joins there is no list of paired devices or a way to revoke one. At minimum show "2 devices open" and a "close sync on other devices" action.
4. **No expiry control for text clips (S).** Files expire after 7 days; text has no setting at all. A per-clipboard "delete after" (1 hour, 1 day, 7 days, never) matches the one-time code story.
5. **No share-as-read-only link (M).** Every link is a full edit link. A view-only link would make "send this to someone" safe.
6. **File downloads are one at a time (S).** A "Download all" for a clipboard with several files.
7. **Quota is only visible in Tools (S).** Show a quiet "x of 10 files, y MB" near the attach control and warn at 80 percent.

### Reliability and trust

8. **Rotate the Supabase secret key (S, you).** It was pasted in chat. Rotate it and update Vercel.
9. **Upload failure recovery (S).** A failed upload shows a row but retry is manual. Add retry on the row.
10. **Offline behaviour is untested (M).** The service worker caches the shell, but there is no test for edit-offline then reconnect.
11. **Cron sweep has no alerting (S).** `removed: 0` is only visible if someone looks. A weekly summary to a log drain or email would catch a silent failure.

### Product polish

12. **Three save signals at once (S).** "Saved", "Autosave on" and "Hosted sync saved" all say roughly the same thing. Keep one status and move autosave into the options menu.
13. **History needs bulk actions (M).** Select several clips to delete, export or pin.
14. **Keyboard map is undiscoverable (S).** There are shortcuts, but no `?` overlay.

## Visual and frontend audit

### Done in this pass

- Landing: quiet drop pill with hover detail (was a baked-in raster card colliding with a grid row), rotating headline word, cursor-driven backdrop and glow, spotlight edge on the paste field, magnetic buttons, scroll reveals, drawn hairlines, cardless sections, variable-weight footer wordmark, paste anywhere on the page, reduced-motion and touch handling.
- App: fixed "Clipboard Clipboard" title, Options button alignment, mobile line-number offset, duplicate Local-first pill and truncated sidebar status.
- Removed unused floating-card components and about 600 lines of dead landing CSS.

### Still open

1. **Performance: two 1 MB PNGs (S).** `pastevault-bg.png` (965 KB) and `pastevault-logo.png` (928 KB). Convert both to AVIF or WebP (expect under 120 KB and 20 KB) and give the logo an SVG. This is the largest first-load cost.
2. **CSS is four layers deep (M).** `styles.css` is 4,300 lines and contains the same selector overridden in three to five media blocks (the code editor surface is the worst). It caused the gutter bug. Consolidate to one rule per component with custom properties, then delete the "final live-QA overrides" blocks.
3. **Dark mode toasts are light (S).** The toast stays white on a dark app. Theme it.
4. **Toast overlaps content on mobile (S).** It sits over the editor and the bottom paste bar. Move above the bar and shorten the copy ("Saved", not "Clip saved successfully / Ready when you are").
5. **Editor header density (S).** Title, three pills, metadata row, and four buttons compete. After removing the duplicate status (feature 12), the header can lose one row.
6. **Mobile top block is heavy (S).** Name, ID pill, status, three action tiles, then tabs before any content. Collapse the three tiles into the existing options menu or a single row of icons.
7. **Type scale (S).** Headings in the app use weights from 760 to 930 in no clear pattern. Define four steps (display, title, label, caption) and apply them.
8. **Focus states (S).** The teal outline works on light but is weak on dark surfaces. Raise contrast on dark.
9. **Contrast of small muted text (S).** `#667085` on white passes AA (about 4.8 to 1) but only just, and the app uses it at 11 to 12 px. Darken to `#566074` for sub-13 px text.
10. **Landing hero on short or wide screens (S).** Verified at 1440 x 900 and 390 x 844. Not yet checked at 1920 x 1080, 1280 x 720 and tablet widths.
11. **Social preview is an SVG (S).** `og:image` and `twitter:image` point at `social-preview.svg`, which most platforms (X, Slack, LinkedIn) will not render. Ship a 1200 x 630 PNG. `landing-background.svg` is unreferenced and can go.
12. **Repo litter (S).** `.codex-backups/` holds tracked copies of old source files. Delete from the tree; history keeps them.

## Suggested order

1. Landing drop attaches files, plus image paste (features 1 and 2).
2. Image compression and logo SVG (visual 1).
3. Single save status, toast theming and placement, mobile top block (feature 12, visual 3 to 6).
4. CSS consolidation (visual 2), with the visual test suite as the safety net.
5. Read-only links and expiry (features 4 and 5).
